# 会话分屏

在 DeepSeek Harness 左侧会话列表中，把任意对话打开到右侧，并继续原来的任务。

## 安装

1. 在 DSH 中打开 **Plugins → Add plugin**。
2. 输入仓库地址 **`https://github.com/homes-mark/dsh-session-split`**，点击安装。
3. 安装完成后启用 **“会话分屏”**。

安装到当前 DSH profile 后生效；不需要先下载或 clone，也不需要额外构建、配置模型或配置工作区。

如果希望手动修改源码，也可以先运行 `git clone https://github.com/homes-mark/dsh-session-split.git`，再在上述安装窗口中输入本地仓库目录路径。

## 使用

1. 在左侧会话列表中右键一个对话。
2. 选择 **“在右侧打开”**。
3. 右侧会出现该会话的完整原生对话界面，左侧仍保持打开前的当前对话。

右侧与左侧使用同一个 Session 身份：历史消息、工作目录、模型选择、运行状态、草稿、工具过程、附件和审批都由 Harness 的原生会话系统提供。插件不会 fork 或新建会话，不会修改模型，也不会自动发送续跑指令。

如果原会话仍在运行，右侧会直接同步当前进度；之后可以通过原生输入框手动发送、排队或停止。右栏的宽度调整、分屏、浮动和全屏操作与其他原生页签一致。

## 完成提醒（2.0.1）

- 右侧正文真实可见且会话成功打开后，已有的绿色完成提醒会被确认；可见期间新完成的任务也不会留下绿点。
- 切到其他页签、收起右栏或切换所属主会话后，隐藏会话随后完成仍保留提醒。浮动窗按原生 `tab.visible` 判断。
- 已经查看过的本轮完成，离开分屏后不会重新提醒；下一轮任务在后台完成时恢复正常提醒。
- 分屏不会获取 `mainView` 引用，不改变中间主会话、左侧选中项、运行状态或审批状态。

### 兼容方式与生效条件

当前实现针对 **DSH 0.2.2-rc.2** 核验。该版本没有公开的完成提醒确认接口，因此插件对 `uiSession.sessionStatus` 的两个公共 observable 方法 `getSnapshot` / `subscribe` 安装可撤销的兼容包装，维护本轮任务的已查看派生状态。它不是官方 ACK API，也不修改 DSH 安装文件、原生私有完成集合或原始状态快照。状态结构或方法属性不兼容时会在激活阶段报错，不尝试强行改写。

**安装或升级后必须刷新当前 DSH 页面，让已有订阅重新建立；如果插件管理器要求重启，则先重启应用再验证。** 不能仅凭热更新注册成功认定提醒逻辑已经覆盖旧页面订阅。

停用插件后会恢复原生完成提醒策略，因此原生尚未确认的旧绿点可能重新出现；在中间主区域打开该会话或开始下一轮任务后，原生状态会自行重置。提前捕获原始方法、绕过公共 observable 的第三方消费者不在本修复的保证范围内。

### 开发与验证

```sh
node build.mjs
node --check client.js
node --test
```

`src/client.js` 是客户端源模板，`src/completion-read.js` 是独立可测试的状态兼容层；构建脚本将它们合成为已导出的 `client.js`，没有新增运行依赖、安装脚本或额外服务器。测试覆盖状态机、订阅/卸载、快照稳定性和接线约束，不替代实际页面验收。

## 实现

右键操作通过 `openTab` 的 `params.targetSessionId` 传递原 Session ID。右侧页签直接 `sessions.retain` 保留该会话，并通过插件独有的 session 级子 Slot 获得 `SessionProvider`，再由官方 `conversation.content` Factory 渲染完整原生界面。消息显示和会话操作没有自定义替代实现。
